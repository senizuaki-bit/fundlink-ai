# 数据飞轮：双端共用的服务端机制

数据飞轮属于 FundLink 的平台架构，不属于投资方或融资方单独拥有的功能页面。两端完成各自的发现、研究、反馈和交易工作；服务端负责把这些动作转成统一事件，在权限范围内更新下一轮画像建议、匹配结果与研究优先级。

架构与当前边界见 [平台架构](PLATFORM_ARCHITECTURE.md)。原 PRD 第 13 节描述反馈闭环，第 14.1 节将行为与业务反馈事件放在业务 API 之后，回流画像及数据库。本次按这一位置调整实现。

## 用户在哪里操作

- 在「发现机会」浏览、收藏、拒绝或研究候选；符合授权条件时记录行为。
- 在「我的画像与资料 → 推荐偏好」管理学习授权、撤回、清除及待确认的偏好建议。个人兴趣建议不能自动修改基金正式授权。
- 在「交易工作台 → 实际业务反馈」记录实际发生的业务进展，保留时间、说明及参考来源，标注为用户自报。模拟交易单独处理。
- 在「证据知识库」核对来源、确认主体关系、复核风险；在监测页面维护公开资料。

侧边栏不再提供「数据飞轮」入口，也不需要用户点击“运行飞轮”才能让反馈生效。原反馈页地址兼容跳转至画像中的授权与偏好管理。

## 服务端闭环

1. 业务 API 校验身份、所属角色、对象权限、工作区版本、数据类型与来源。
2. 将通过校验的工作区变化投影为平台统一事件。两端使用同一个事件结构，交易对始终按“企业—投资机构”排列。
3. 平台事件只保存计算所需的类型、对象标识、时间、来源类别和授权状态，不复制 BP 正文、业务备注或证据原文。
4. 共用推荐服务读取已保存画像、当前身份可见证据和允许使用的事件，进行硬条件筛选、双向适配与轻量反馈排序。
5. 推荐页与 Agent 使用同一服务端匹配链路。新证据和复核继续进入原有研究流程；偏好变化仍需用户确认。

工作区行为和业务反馈在保存时同步投影。来源采集、风险复核和主体关联的元数据在下一次服务端推荐读取时同步；目前不是每次证据写入即推送的实时事件流。已有 `/api/flywheel` 诊断接口保留查询和保存评估能力，但不作为双端功能入口。

“平台统一”是服务及数据契约统一。事件带有账户、角色与权限范围，不意味着所有客户互相读取私有材料。现阶段未认领主体仍用当前范围内的标识；名称相同、网址相似或切换投资/融资身份都不会自动合并成同一真实交易对，也不会生成对方的同意。

## 授权与学习规则

- 行为学习默认关闭。仅本次主动授权后的近 90 天事件用于学习，30 天半衰减；不追溯授权前的浏览和收藏。
- 同一对象与信号类型取最新一次。曝光不直接加分，按不同曝光对象数归一化，并采用平滑先验。
- 浏览、搜索等弱信号只轻微影响当前对象，不独立生成行业偏好或扩散至相似对象。
- 偏好建议需要多个不同对象及足够的兴趣信号，用户可确认、忽略、撤销。
- 行为调整保持 −3 至 +6 分；明确确认的偏好额外影响单侧 2 分。行业、阶段、金额、币种、拒绝与身份等约束不因反馈而放宽。
- 真实来源与模拟案例分开学习。真实主体上的模拟交易进度也不增加真实业务排序权重。单侧登记的会谈、尽调或成交保持“用户自报”。
- 撤回后停止使用学习信号；清除后移除行为信号及派生评估，保留用户明确要求保留的业务记录、收藏和显式偏好。
- 源工作区更新与事件投影使用版本校验。并发失败不能保留过期投影或恢复已撤回的授权。

## 内部评估口径

保留已有诊断与历史评估能力作为内部核查基础，不在双端业务侧边栏中呈现平台运营面板。指标限当前账户、当前角色及实际留存窗口，不能用局部数据冒充全站效果。

资料覆盖、主张追溯、主体关联确认、人工复核误报和来源新鲜度都有明确分母。没有样本显示“暂无样本”。人工确认关联的比例不等于经过独立核验的实体对齐准确率。

业务转化按真实曝光对象去重，业务实际发生时间必须晚于曝光。补录早于曝光的历史业务不计作推荐转化，不用后期阶段反推早期阶段已经发生。排序对照固定候选、硬条件与明确偏好，仅切换行为调整；名次变化不能证明因果效果改善。

现有知识快照最多包含 250 个主体、1,000 个来源、3,000 条主张、1,000 条关系及发现；行为最多保留 500 条，实际业务登记最多 200 条，内部评估最多 30 轮。超出留存窗口的数据不推算。

## 已实现与待接通

本次实现双端共用的事件模型、服务端投影与推荐消费链路，以及原有授权、偏好建议、风险复核和业务反馈。使用可解释规则，不宣称已经训练新的共享模型。

实现入口：

- `lib/platform-flywheel.ts`：统一事件、企业—机构方向、来源分级、授权学习投影与交易对摘要。
- `lib/platform-flywheel-server.ts`、`drizzle/0004_platform_flywheel.sql`：有权限范围及版本保护的持久化事件投影。
- `lib/recommendation-server.ts`、`/api/recommendations`：两端及 Agent 共用的服务端推荐；读取失败不会回退为浏览器自行计算行为排序。
- `components/preferences.tsx`、`components/business-feedback.tsx`：画像和交易中的用户控制入口。
- `scripts/verify-recommendations.mjs`、`scripts/verify-platform-flywheel.mjs`、`scripts/verify-flywheel-api.mjs`：实际 SQLite 验证事务、隔离、并发、撤回与共用消费链路。

真正跨账户的企业/机构认领、组织成员授权、双方共享 Deal Room、双方独立确认与外部业务回执仍需接入。当前没有把一家机构的私有尽调资料用于另一家机构的推荐，也没有把单侧业务登记当作真实对方反馈。双边网络效应与平台整体融资成功率尚未验证。

升级运行 `npm run db:init`，再运行 `npm run dev`。统一事件与规则推荐无需模型密钥；主动使用 Agent 时仍遵循模型和资料访问权限。
